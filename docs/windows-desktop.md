# Windows desktop application

Windows users install DSH Forge with `DSH-Forge-VERSION-Setup.exe` from the
official GitHub release. The per-user installer does not require administrator
access. It creates a Start Menu shortcut, offers an optional desktop shortcut,
and replaces the previous application files on an upgrade. User state stays in
`%LOCALAPPDATA%\DSH Forge` and is not removed by an application update.

The executable bundles the Python sidecar and static interface. It opens the UI
in the installed Microsoft Edge app-window runtime, with Chrome or the default
browser as fallbacks. It does not bundle Electron or a second Chromium runtime.
On startup it scans the normal DSH locations and the previously saved folders
without executing candidate code. It also refreshes the public catalog when a
network connection is available, retaining the last good local snapshot when
offline.

## Windows isolation boundary

Catalog browsing, DSH discovery, and local metadata inspection work natively on
Windows. Apptainer does not provide a native Windows execution backend. Secure
plugin, fork, and isolated Harness execution therefore remains disabled in the
Windows process. Those operations require DSH Forge in WSL2 or a remote Linux
host with a pinned Apptainer image and a passing capability probe. The desktop
UI reports this boundary explicitly and never falls back to executing community
code directly on Windows.

## Build locally

Use 64-bit Python on Windows, then install the pinned build dependency and Inno
Setup:

```powershell
python -m venv .venv-build
.\.venv-build\Scripts\Activate.ps1
python -m pip install -r packaging\windows\requirements-build.txt
winget install --id JRSoftware.InnoSetup --exact --version 6.7.3
.\packaging\windows\build.ps1 -Version 0.1.0
```

Artifacts and SHA-256 checksums are written to `dist\windows`. Pass
`-SkipInstaller` to build only the portable zip.

The build pins Inno Setup 6.7.3. Its publisher requests that commercial users
purchase an Inno Setup license. The current research build does not add a
commercial license key to CI. Purchase and configure the appropriate build
license before using this pipeline for a qualifying commercial distribution.

## Trusted signing

Unsigned local builds are intentionally labeled by the build script. Public
release artifacts should be signed with a CA-backed Authenticode certificate
whose private key is available in the current user's Windows certificate store:

```powershell
.\packaging\windows\build.ps1 -Version 0.1.0 -CertificateThumbprint CERT_THUMBPRINT
```

The script signs and verifies both the application executable and final
installer with SHA-256 and an RFC 3161 timestamp. CI accepts the same
thumbprint after importing a release certificate from encrypted repository
secrets. A certificate cannot be generated by this repository because a local
self-signed identity would still trigger Windows trust warnings.

## Updates

Packaged builds check the official GitHub latest-release API once at startup.
When a newer semantic version exists, the header links to its official release
page. Forge does not silently download or execute an update. The downloaded,
signed installer performs an in-place upgrade using the stable installer app
identity.
