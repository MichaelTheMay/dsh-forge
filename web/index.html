How picks work

No AI guessing. Every day we measure each project the same way, then look for the gap between how well it’s built and how much attention it gets.

  1. How it’s built. Tests, CI, docs, releases, a license, and steady recent work.
  2. What that usually earns. A model trained on the whole catalog predicts the stars a project built like this tends to have.
  3. The gap. Projects with far fewer stars than predicted rise to the top.
  4. Someone else noticed. Stars from Harness contributors and plugin authors, merged pull requests, and outside contributors count as real-world checks.

The prediction is tested on projects it wasn’t trained on. If it doesn’t hold up that day, picks fall back to a simple equal-weight quality score instead.

Archived, unlicensed, abandoned, or barely documented projects are left out. Forks are judged only on what they changed, and a fork of a fork can’t borrow its parent’s work.
